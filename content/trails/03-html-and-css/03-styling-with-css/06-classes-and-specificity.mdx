<Analogy title="School uniforms and name badges">
A school says "everyone in Grade 12 wears a blue tie". That's a **class**: a group rule. One learner has a **name badge** with a special instruction. That's an **id**: it's for exactly one person, and it's more specific, so it wins.
</Analogy>

## Classes: styling a group

Add a <Term word="class">class</Term> to any HTML elements you want to style together:

```html
<p class="note">Bring your ID.</p>
<p class="note">Arrive by 8.</p>
```

In CSS, a class selector starts with a **dot**:

```css
.note {
  color: green;
}
```

An **id** is written `id="welcome"` and must be **unique**: one per page. In CSS it starts with a **hash**: `#welcome`.

## Who wins? Specificity

When two rules give the same element different values, the browser uses <Term word="specificity">specificity</Term>: the more *specific* selector wins.

1. **id** (`#welcome`): the most specific. It's for exactly one element.
2. **class** (`.note`): in the middle.
3. **element** (`p`): the least specific. It's for every element of that type.

If two rules are **equally** specific, the one written **later** in the stylesheet wins.

Because ids win so strongly, most developers style with classes and avoid id selectors. That's exactly what causes the bug below.

## Fix the bug

The school wants **both** notes green and bold, and the last paragraph left normal. But the first note is black, and neither note is bold. Find the two problems.

<KeyIdea>
Style groups with **classes** (`.name`). When rules disagree, **id beats class beats element**, and if they're equal, the later rule wins.
</KeyIdea>
