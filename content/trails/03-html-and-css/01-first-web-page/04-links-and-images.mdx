<Analogy title="A signpost and a photo frame">
A **link** is a signpost: it says "go this way" and names the place. An **image** is a photo frame with a little card underneath describing the photo, for anyone who can't see it.
</Analogy>

## Links: the a element

Links are what make the web a *web*. They use the `a` element (short for "anchor"):

```html
<a href="https://www.gov.za">South African Government</a>
```

- `href` is an <Term word="attribute">attribute</Term> that holds the address the link goes to. It's short for "hypertext reference".
- The words between the tags are what people tap. Make them describe where the link goes. "Click here" tells nobody anything, especially someone using a <Term word="screen-reader">screen reader</Term>, which can read out a list of every link on a page.

## Images: the img element

```html
<img src="table-mountain.jpg" alt="Table Mountain with a cloud on top">
```

- `src` (source) is the image file to show.
- `alt` is the <Term word="alt-text">alt text</Term>: a short description of what the picture shows. Screen readers read it aloud, and it appears if the picture can't load.
- `img` has **no closing tag**. There's no content to wrap; the picture is the content.

**In this practice area**, the preview doesn't download pictures from the internet (to save your data), so you'll see your alt text where the picture would be. That's a good test of whether your alt text makes sense on its own!

<KeyIdea>
A link is `<a href="address">words</a>`. An image is `<img src="file" alt="description">`. Always write alt text, and make link words describe the destination.
</KeyIdea>
